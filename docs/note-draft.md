# 「次はどのライブに行く？」を考える推し活カレンダーをCodexで作った

推しのライブやイベントを追いかけていると、予定を確認するだけでも意外とページを行き来します。

今回は、OCHA NORMA、モーニング娘。'26、宮本佳林の予定を、ひとつの月間カレンダーで見られるWebアプリを作りました。

このアプリの目的は、公式サイトの代わりになることではありません。「この月はどのライブに行けそうか」「ライブ以外にどんなイベントがあるか」「チケットの受付状況を確認したい予定はどれか」を、推し活の作戦会議を始める前に見渡せるようにすることです。

## きっかけは、予定を比較しにくかったこと

アーティストごとのスケジュール、ツアーの詳細、リリースイベント、チケットのお知らせは、同じページにまとまっているとは限りません。正式名称を検索しながら開催地や種別を確認していると、「同じ月の予定を並べて、どれに行くか考える」という最初の段階に時間がかかります。

そこで、まずは3組の予定をひとつの画面に集め、日付・場所・イベント種別を比較しやすくしました。自分の中で行われている「どのライブに行くか作戦会議」を、カレンダー上で始められるようにするイメージです。

## 作ったアプリでできること

アプリには、2026年8月22日時点で確認した公開情報を、40件のイベントとして登録しています。

- 3組のアーティストを色分けして表示
- ライブ、フェス、ステージ、オンライン、BDイベント、個別イベントで絞り込み
- カレンダー上では「北原ももBD」「秋ツアー福岡」「リミスタ（サイン会）」のように主題が分かる短い表示
- 日付を選ぶと、会場、出演者、チケット状況、受付期間、公式リンクを確認
- 期間イベントは、開催期間中の日付に表示

カレンダーを開いたときに正式名称の長い文字列を読むのではなく、まずは「何の予定か」を短く把握できるようにしました。

![推し活カレンダーのイベント詳細画面](./local-preview-detail-viewport.png)

日付をクリックすると、選択したイベントの詳細が表示されます。北原ももBDイベントの例では、会場、開場・開演時間、当日券の受付状況、受付期間、公式情報へのリンクを確認できます。

## チケット情報はどう扱ったか

チケット情報は、確認できた公式ページの内容を、アプリで使うために短く整理しています。例えば北原ももBDイベントでは、2026年8月22日時点で公式の公開ページに掲載されていた当日券予約販売の案内を確認し、アプリには「当日券受付中」「受付期間 8/21〜8/26」と表示しました。

公式ページの文章を長く転載したり、画像を取り込んだりするのではなく、開催日・受付状況・公式リンクという確認に必要な項目に絞っています。受付状況は変わる可能性があるため、申込みの前には必ず公式ページを確認する前提です。

## 自動取得にしなかった理由

将来的には、新しいイベントの追加や受付状況の変更を自動で確認できるようにしたいと考えています。ただ、最初から自動巡回まで含めると、ページごとの表記ゆれ、会員向けページの扱い、受付中から終了への変更判断など、画面以外の問題が大きくなります。

そこで今回は、まず「どんな情報を、どんな粒度で見せると使いやすいか」を確かめるため、確認日を明記したスナップショットとして作りました。現在のアプリは自動取得・自動更新を行いません。

## Codexに任せたこと、人が判断したこと

Codexには、React・TypeScript・Viteによる画面実装、カレンダー表示、フィルター、イベントデータの構造化、短縮表示、ビルド確認を依頼しました。

一方で、どのアーティストを対象にするか、イベント名をどこまで短くするか、公式リンクを残すこと、公開情報だけを扱うこと、会員ログインが必要な情報を掲載しないことは、人が判断しています。

AIがページの内容を整理できても、その結果が正しいか、公開してよい範囲かを確認する責任まで自動化できるわけではありません。今回のアプリでは、公式ページとの照合と、確認日を残すことを重視しました。

## 公開しているデータについて

掲載しているのは、確認日時点で公式サイトから一般に閲覧できた予定や、そこから整理した短い事実情報です。ログインが必要なページの内容、会員番号などの個人情報、公式サイトの画像や長文本文はリポジトリに含めていません。

FC向けイベントであっても、イベントの開催告知が公式の公開ページで確認できる場合は、開催日・会場・受付状況などを必要最小限に整理し、元の公式ページへのリンクを残しています。掲載情報の利用や転載については、各公式サイトの規約・権利条件に従う必要があります。

## 今使える範囲と、これからの改善

現在は、予定の全体像を確認し、イベント種別やアーティストで絞り込む用途に使えます。一方で、チケットの販売状況を保証するサービスではありません。スナップショット以降に変更された情報や、新しく追加されたイベントは反映されていない可能性があります。

今後は、次のような仕組みを検討しています。

- 公式の公開ページを対象にした新規イベントの発見
- 既存イベントの日時・会場・受付状況の変更検知
- 変更の根拠URLと確認日時の保存
- 判断できない情報を公開せず、確認待ちにする仕組み

自動更新を追加する場合も、会員限定情報を取得しないこと、長文転載をしないこと、根拠URLがない変更をそのまま公開しないことを条件にします。

## まとめ

今回は、推しの予定を探すために複数の公式ページを行き来する負担を減らし、「次はどのライブに行く？」を考えやすくするカレンダーを作りました。

自動取得まで一気に進めるのではなく、まずは見たい情報の形を決め、公式リンクと確認日を残したスナップショットにしています。Codexを使うことで実装とデータ整理は速く進められましたが、何を掲載し、どこまで公開するかの判断は人が行う必要があります。
