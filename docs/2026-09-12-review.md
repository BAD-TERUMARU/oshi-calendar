# 現場記録の追加と既存カレンダーのレビュー

## 変更の目的

既存カレンダーでは参加した現場やセトリ、支出を記録できなかったため、現場記録・振り返り・生涯セトリを追加した。公式の開催情報と個人の体験記録は分け、実績や曲目のサンプルデータを初期登録しない。

基準となるGitHub main: `335d2c51129757550b721e111592d7329c309b98`。元の全ファイルを取得し、Git blob SHAで照合した。元ツリーは `0ec21e9b325d9074d76fd5dc3255fd6d97240c59`。

## 実装した機能

- カレンダーの「行きたい」から公演単位で参加予定を作成。安定した公演IDで重複を防ぐ。
- 過去の現場を手入力し、参加状態、アーティスト、会場、座席、感想、評価、支出、セトリを編集。
- 参加済みだけの公演数・会場数・曲数・支出、月別・アーティスト別の公演数を集計。
- 曲別に聴いた公演数と初回・最終回を表示し、その現場へ戻れる。
- バージョン付きJSONを厳密に検証して取り込み。同一IDを上書きせず、破損したファイルは全件を拒否。
- 容量不足時は画面上の記録を保持し、未保存を警告してJSONへ退避できる。保存済みデータの読み取り失敗や別タブとの競合では上書きを止める。
- 画面切替で編集中の入力を保持し、別の編集対象へ切り替える際は変更破棄を確認。

個人の記録は端末内保存で、アカウント同期は実装していない。共演は登録したアーティスト表記の組み合わせとして集計する。モーニング娘。の年号付き表記は生涯集計で同じグループへまとめる。

## レビューで修正した問題

| 問題 | 修正 |
|---|---|
| 無料観覧イベントの優先エリア抽選締切が、観覧全体の受付終了に見える | 無料観覧と「優先観覧エリア抽選」の期限を分けて表示。ラベルは既存の告知メモから設定 |
| ICSのアーティスト・確認日・期限経過の変化が変更検知に含まれない | 実際の説明文と不足していた属性を署名に含める。単なる公演の並べ替えでは誤検知しない |
| 共演者がICSと一部の画面から欠落する | 主アーティストと共演者の重複を除き、併記 |
| スマホのカレンダーから詳細が見つけにくい | 日付選択で詳細見出しへフォーカスとスクロール。動きを減らす設定を尊重 |
| 補助ラベル・曜日・OCHA色のコントラストと小さすぎる文字 | 色と小画面のチップ文字サイズを調整 |
| Workerの同梱データ日時が古く、API説明が画面実装と不一致 | 日時の参照元を共通化し、現在の画面が静的データを直接使うことを文書化 |
| 新UIの画面切替や編集対象切替で入力が失われる | 編集フォームを保持し、未保存時の対象切替を確認 |

## 検証

`npm test` の35件と `npm run build`、`git diff --check` が成功。

- 既存カレンダーとICS: 日付・JST、安定した公演ID、旧選択の移行、時刻、期間、公演ごとの選択、UTF-8折り返し、終了予定の検証。
- 個人記録: 参加状態ごとの集計、セトリの正規化、グループの年号、重複防止、JSON往復、不正な日付・金額・参加状態の拒否。
- jsdomとReactによる実DOM操作7件: 新規/既存の編集中入力の維持、変更破棄のキャンセル、保存後の再マウント、不正JSONの原子的拒否、容量超過時の保持とバックアップ、別タブ競合と再読み込み。

実ブラウザからローカル開発URLへの接続は `ERR_BLOCKED_BY_CLIENT` となり、375px/1280pxでの実ブラウザ操作・レイアウト確認は未実施。DOM試験はその代替範囲を限定しており、ピクセル単位の表示検証をしたとは扱わない。

## 本番反映

この作業環境ではCloudflare用の接続、CLIログイン情報、APIトークンを確認できなかったため、本改修は本番未反映。既存公開URLを新実装の動作確認結果として扱わない。変更はGitHubの開発ブランチとドラフトPRへ保存する。

Cloudflareへ接続できる開発環境で `npm ci`、`npm test`、`npm run build` を実行し、実ブラウザで現場登録・再読み込み・ICSを確認した後に `npm run cf:deploy` で反映できる。公開直前にはmainおよび公開版との更新差分を再確認する。
